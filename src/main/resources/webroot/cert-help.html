Install the localReceiver certificate

One-time step per device. Afterwards this server — and every future localReceiver session from the same computer — opens without warnings, and the page can be installed as an app.

First download the certificate: localreceiver-ca.crt. Then follow your platform below. The certificate is generated on the computer running localReceiver and never leaves your network. It is limited to local addresses (localhost and private network IPs), so it cannot vouch for any public website.

Check the fingerprint on the device, not on a web page. The localReceiver window on the host computer (or its console, when it runs without a window) shows the certificate's SHA-256 fingerprint. Each platform below says where the device itself shows the SHA-256 of the certificate you downloaded. If that differs from the host's — ignoring colons, spaces and upper/lower case — do not trust it (or remove it again): someone on the network may be impersonating the server. A substituted certificate could vouch for any website until you remove it, so this check matters. Do not rely on any fingerprint shown by a web page, this one included.

iPhone / iPad (iOS, iPadOS)

  1. Download localreceiver-ca.crt in Safari and tap Allow when asked to download a configuration profile.
  2. Open Settings — a Profile Downloaded entry appears near the top. Tap it and tap Install.
  3. Before trusting it, open Settings → General → VPN & Device Management, tap the localReceiver CA profile → More Details → the certificate, and compare SHA-256 under Fingerprints with the host's. If it differs, tap Remove Profile instead.
  4. Then go to Settings → General → About → Certificate Trust Settings and switch on full trust for localReceiver CA.
  5. Reload the localReceiver page.

Android

  1. Download localreceiver-ca.crt.
  2. Open Settings → Security & privacy → More security settings → Encryption & credentials → Install a certificate → CA certificate (wording varies by vendor).
  3. Choose Install anyway and pick the downloaded file.
  4. Open Encryption & credentials → Trusted credentials → User, tap localReceiver CA, and compare its SHA-256 fingerprint with the host's. If it differs, tap Remove.
  5. Reload the localReceiver page.

Windows

  1. Download localreceiver-ca.crt.
  2. Check it first: in a terminal run certutil -dump localreceiver-ca.crt and compare the Cert Hash(sha256) line with the host's. Do not continue if it differs. (The Thumbprint in the certificate dialog is SHA-1, not SHA-256.)
  3. Open the file, click Install Certificate…, choose Local Machine (or Current User).
  4. Select Place all certificates in the following store → Trusted Root Certification Authorities → finish.
  5. Restart the browser.

macOS

  1. Download localreceiver-ca.crt and open it — Keychain Access imports it.
  2. In Keychain Access, find localReceiver CA (System or login keychain), open it, expand Trust, and set When using this certificate to Always Trust — but first compare SHA-256 under Fingerprints in the same window with the host's; if it differs, delete the certificate instead.
  3. Restart the browser.

Linux

  1. Check the file first. grep -c 'BEGIN CERTIFICATE' localreceiver-ca.crt must print 1, and openssl x509 -in localreceiver-ca.crt -noout -fingerprint -sha256 must match the host's. Do not continue otherwise — a file holding a second certificate would have it trusted too.
  2. System-wide (Debian/Ubuntu): sudo cp localreceiver-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates (Fedora: /etc/pki/ca-trust/source/anchors/ + update-ca-trust).
  3. Chromium and Firefox keep their own store — import via the browser's Settings → Privacy/Security → Certificates → Import, trusting it for websites. Firefox's View button shows the SHA-256 fingerprint to compare.
  4. Restart the browser.

To undo, remove "localReceiver CA" from the same certificate store. If the server's certificate ever stops matching (for example the computer's address changed), delete keystore.p12 in the server's ~/.config/localreceiver/ — a fresh certificate is issued from the same CA, so devices stay trusted.
